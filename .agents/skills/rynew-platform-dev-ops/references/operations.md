# 功能运维与排障

## 先确定运行事实

记录本次目标、程序提交/摘要、前后端版本、数据库升级基线、外部配置路径、进程命令行和最近错误时间。配置只查看键与脱敏状态；日志避免输出Token、密文、口令和业务正文。先做和症状直接相关的只读检查，再决定最小修复。

本技能检查器只验证仓库信息，不检测现场服务。部署/数据库/设备范围须来自本次授权；用户已给过同一目标和操作授权时直接继续，不重复审批。诊断请求完成原因分析即可，不自动重启、清Redis、跑迁移或重新执行任务。

## 基础功能操作

| 操作 | 检查点 |
| --- | --- |
| 建账号/角色 | 部门岗位、状态、角色菜单和按钮；最小授权，变更后重新登录确认 |
| 新业务菜单 | path/component/name、后端RouterVo、菜单可见/启用、按钮perms与API权限一致 |
| 字典/参数 | 字典类型、值类型/颜色、内置保护、缓存刷新；不能绕过保护改库 |
| 文件协作 | 用户模块权限、文件ACL/期限、owner和额度分别校验 |
| 巡检运维 | 目标→模板步骤→范围→计划/调度→执行记录→目标证据/健康聚合 |
| 数据治理 | 资源可用、连接/版本、任务revision、真实run终态、归档/接收端回读 |

## 登录和权限链

`SysLoginController` → `SysLoginService` → 认证与 `TokenService.createToken` → Redis会话 → JWT返回；后续 `JwtAuthenticationTokenFilter` 从Bearer令牌恢复LoginUser。前端cookie为 `Admin-Token`，请求由 `utils/request.js` 统一处理。

后端业务JSON的code=401可能以HTTP200返回，不能只看状态码。排查时沿失败请求令牌、当前cookie、Redis对应会话和服务日志匹配；只记录不可逆摘要或脱敏标识。

| 现象 | 检查顺序 | 不应先做 |
| --- | --- | --- |
| 登录后立即退出 | 请求和cookie是否一致→token.secret/节点→Redis库/TTL→时钟→logout请求 | 清空全部Redis或全体用户会话 |
| 页面看不见/按钮缺失 | 用户角色→sys_role_menu→菜单状态/组件→getInfo/getRouters→前端权限 | 用前端强行显示按钮绕过后端 |
| 有按钮但403 | Controller权限字符→角色授权→对象归属/ACL→新会话 | 把接口加permitAll |
| 多页签互相踢下线 | 失败页签令牌与共享cookie、logout时序、Redis会话删除对象 | 未取证就重启或归咎Token超时 |

## 服务/数据库/文件常见问题

| 现象 | 最小核验 |
| --- | --- |
| Nginx502 | 后端进程/端口、启动失败原因、proxy_pass、网络；先确认后端可用 |
| 页面刷新404 | dist根目录index.html、try_files回退、实际前端base/API前缀 |
| 数据库连接失败 | 外部配置是否生效、URL/账号、网络、TLS/时区；不打印密码 |
| Unknown column/table | 当前Mapper/Service需要的结构与独立升级SQL、实际库结构；不要直接跑新库初始化 |
| 上传413或文件被拒 | Nginx、Spring multipart、文档全局/单用户/压缩/PDF限制及剩余额度 |
| Office打开失败/不落版本 | 编辑器URL、双向回调/文件取回、JWT、可信下载主机、storageKey与实际回调状态 |
| 凭据无法解密 | 区分使用哪个凭据实现→原有效密钥→密文来源/迁移；保留原配置，不直接换密钥 |
| 扫描核验成功却同步失败 | 任务阶段、root核验、Sync事务、异步SecurityContext与审计无请求分支 |
| HDI“完成”无业务输出 | 原日志/行告警、冻结连接revision、文件摘要、目标回读；不得仅凭finish判成功 |

后端基础活性可用 `curl -fsS http://127.0.0.1:8080/captchaImage` 检查响应；验证码可用不等于数据库登录和全业务可用。已有部署命令应替换为现场实际地址和进程，不用宽泛pkill。

## 计划与异步任务

巡检计划由quartz的ScheduleService管理sys_job及调度器；只改 `sup_auto_inspection_plan.status` 会失配。排障核对jobId、invokeTarget、cron、状态、模板/目标和有效窗口。需要停止时走现有业务启停接口，确认当前执行已结束。

文档权限到期任务、IPAM租约扫描、现场服务器扫描和原生HDI计划各有不同生命周期，不共用巡检恢复方案。HDI未知状态不自动重放，设备认证失败不无限重试，IPAM锁不手动无条件删除。

## 备份与回退的对象

- MySQL备份和匹配的增量/检查SQL；数据变动前核对恢复可行性。
- 现行成套前端/JAR、外部配置、原有效密钥；记录摘要和来源提交。
- 文档文件、版本和ACL/额度；文件与数据库同一恢复点。
- 数据治理私有状态、任务/连接版本、归档文件、bundle/适配包摘要及配置。
- 正在运行的任务和调度状态，避免切换后双跑或重放输出。

应用回退优先切旧成套制品并保留新增表/数据；DDL常有隐式提交，不能宣传整个升级可事务回滚。整库恢复会覆盖上线新增数据，必须先明确范围和时间点。真实目标的危险操作只在其已确认授权范围执行。

## 交付与手册

从确切、干净的main提交/标签创建独立detached发布worktree；记录commit和dirty检查。按本次模块清单检查后端类/依赖、dist页面/API/权限、SQL表/菜单/任务、配置和手册。交付SQL只含约定技术数据/虚构演示，不导出现实场景、IP、联系人、密码或执行记录。

维护简单部署手册：数据库入口→两个YAML→java -jar脚本→dist和Nginx→验证。配置截图使用无秘密的真实文件；操作手册截图来自本次实际操作页面，标明演示范围，不用生成图冒充真实截图。文档生成、视觉检查和PDF交付使用当前可用文档工具，不为本技能引入固定个人机器路径。

最后按内容生成校验清单，验证归档与解压后文件一致。报告“源码/测试/构建/部署/真实业务”的实际完成层级，不把历史测试数字或别的环境结果复制为本次证据。
