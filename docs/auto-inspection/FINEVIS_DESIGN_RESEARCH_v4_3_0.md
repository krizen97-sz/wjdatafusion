## 实景观察

通过用户已登录的 Chrome 会话查看了以下模板，而非仅凭产品宣传图推测：

| 模板 | 值得借鉴 | 不直接照搬 |
| --- | --- | --- |
| 写字楼物业数据可视化大屏 | 三维场景承担主体，周边用少量图表补充运营状态，主次清楚 | 巡检数据没有可信地理坐标或完整建筑模型，不虚构地图和孪生场景 |
| 设备状态检修 | 将设备对象、检修状态和检测趋势围绕同一业务对象组织 | 超宽模板在普通浏览器中形成大量上下留白，文字随整页缩放过小 |
| 智慧工厂运营管控平台 | 场景视角和专题入口相互关联，局部内容随业务主题变化 | 不将装饰边框、持续扫描和三维素材搬入普通后台控件 |

## 技术参考

- [FineVis 数据可视化简介](https://help.fanruan.com/finereport/edition-view-60129-22.html)：介绍 B/S 编辑模式、图表/媒体/三维/控件等组件及多种自适应方式。本项目提炼布局思想，不接入编辑器或商业运行时。
- [FVS 组件刷新](https://help.fanruan.com/finereport/doc-view-5303.html)：仅刷新数据、保留交互状态及错误时保持展示，适合长期值守。此次采用现有接口轮询，不宣称具备服务端推送。
- [FVS 扩展图表轮播联动](https://help.fanruan.com/finereport/doc-view-5411.html)：组件间传递业务参数是联动核心。此次用明确的范围/状态筛选实现联动，不添加自动轮播抢占用户操作。
- [ECharts 容器与尺寸](https://echarts.apache.org/handbook/en/concepts/chart-size/)：复用已安装 ECharts 5.6 和 ResizeObserver，按真实容器重绘，不升级依赖。
- [ECharts 异步加载与动态更新](https://echarts.apache.org/handbook/en/how-to/data/dynamic-data/)：稳定系列标识和 setOption 数据更新支持短时连续过渡。

## 原有问题与改动

| 问题 | 处理 |
| --- | --- |
| 六图表分三排，1728x940视口中的内容约1295px高 | 主次明确的两排网格；当前常规视口内容856px，窄屏切换为多排而非缩小字体 |
| 双环总数来自最多12条的排行结果 | 构成和总量直接使用全部现场、全部主平台，排行保留全部行 |
| 状态扇区随机跳到第一个匹配对象 | 扇区先联动层级与状态筛选，再由具体对象进入结果 |
| 0%条形没有可点击面积，重名计划容易混淆 | 坐标轴名称启用事件，用 scopeKey/planId 定位，不用可见名称或排序索引定位 |
| 最近记录按数组索引等距离排列 | 使用真实时间刻度，按时间排序，剔除无效时间值 |
| 刷新清空数据及图例/缩放状态 | 保留最近成功数据；按稳定视图键保留图例、缩放，筛选变化才重置 |
| 图表主题、空态、交互缺少统一测试 | 保留模块级 ECharts 容器，并将图表配置与纯数据函数分离测试 |

## 验收边界

- 真实页面：现有登录会话与本地后端，验证状态筛选、0%名称下钻、全屏进入/退出、手动刷新及失败恢复。
- 多数据场景：仅在浏览器拦截单次驾驶舱查询响应，使用20个范围、20个计划和9条执行记录进行密度测试；没有写入数据库。测试结束清除拦截并恢复真实接口。
- 不做生产部署，不新增数据库脚本，不修改原有执行计划或巡检结果。
- 自动化操作后台标签页时浏览器拒绝原生全屏；切换为活动标签页后已正常验证，不绕过浏览器权限。
- 本次本地截图位于 `output/finevis-research/`，属于验收产物，不纳入源码提交。
- 已检查1920x1080、1728x940、1366x768、800x900和390x844视口，未发现面板重叠或横向溢出；原生全屏、键盘范围选择、空态、真实对象下钻和失败恢复已验收。
- `npm run verify:frontend` 通过122项测试并完成生产构建，UI Guard为0错误、0警告，Impeccable机械检测无发现。
- 根目录旧设计文档仍有表格型驾驶舱的历史描述；本次遵循当前v4.2.5全图表实现和最新版本记录，不扩展修改全局设计文档。

## 后续适用条件

如需进一步引入真实地理态势、三维机房与健康范围联动，应先确认坐标、设备标识及告警归属的可靠性，再单独规划数据合同。配置型大屏编辑器、远程控制和推送刷新属于新的产品能力，不应只为视觉效果引入额外运行时。
