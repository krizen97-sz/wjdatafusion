# 数据治理 v4.7.0：完整产物与批次交付

本地入口`https://localhost:10443/governance/workspace`。本版为隔离开发环境，未连接导出任务中的生产源、目标或旧消费组。

## 完整产物

运行结果预览仍有条数/长度上限。交付另外读取真实NiFi捕获队列中的全部成功输出：最多100个文件、单文件8MiB、合计32MiB，流式保存并核对引擎声明长度。任何截断、取消、数量不完整、失败或未确认清理都不能发布交付清单。

只有`SUCCEEDED + cleanupConfirmed`发布manifest。文件保留原安全文件名，实际本地路径全部为UUID；目录700、文件600，清单记录顺序、字节数和SHA-256。读取在同一文件句柄上再次校验，提前中止不会视为完整读取。旧运行仅有预览时需重新执行，不能用预览拼出“完整文件”。

下载采用原鉴权请求内的有界流式响应，避免现有JWT链在异步重新分发时拒绝已提交响应；未改变全局鉴权策略。

## FTP交付

连接密码复用平台加密能力。目标须在服务端`data-governance.ftp-allowed-endpoints`内，默认只有`127.0.0.1:2121`；明确IPv4地址、既有根目录、BINARY/ASCII及控制编码。服务端需支持MLSD和文件回读，目录读取限制64KiB/210条及绝对时限，不完整结果不会被当作“文件不存在”。

每次交付创建独立批次目录。流程为：验证原运行持久成功/清理及完整产物 → 上传`.temp` → 回读字节与摘要 → 改最终名并复核 → 最后发布`_SUCCESS.json`。接收方必须按完成标记判断整批可用。ASCII若改变实际存储字节，校验会失败；没有将它自动当成BINARY。

同一run/connection重复提交返回原交付。源文件一直保留。重试核对已上传文件，不覆盖内容冲突的最终文件；如果已有完成标记，则只核对整批，不重新补传接收方可能已经取走的文件。状态不明确时保持待核查。

显式使用当前凭据重试时，主机、端口、目录、传输和控制编码必须一致；目标版本及凭据版本分别记录。计划绑定的目标指纹还包含username，因而改变身份不能被当成仅换密码。

该默认是新的交付契约，不是原FTP平铺目录扫描/删除源文件/最多80文件的无损复刻。原文件命名时钟、接收目录规则和消费完成标记的方式需要现场确认后再切换。

## 定时任务

计划可绑定可选FTP目标。先持久执行意图，使用发布时冻结的处理图、输入、参数和字典；原运行成功、清理和完整manifest均确认后才调用交付。FTP未完成时仍保留执行占用，Cron与手动触发都不能重叠。

只有交付返回`DELIVERED`且实际冻结目标指纹一致才释放占用；EMPTY明确跳过交付。重启、未知效果或失败后暂停，核查恢复只读取已有运行/交付，不重新执行ETL或补传。交付缺失、错误目标、未确认清理不能猜成成功。
