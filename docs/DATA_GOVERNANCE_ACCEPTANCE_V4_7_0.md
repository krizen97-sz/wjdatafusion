## 原插件对照与修复

原JsonInput共81个向量、消息改写24个向量、真正NiFiMock trim→Writer的9个文件向量分别核对状态、字段或完整字节。日期固定调用官方Rhino原生Date.parse，UTC/Asia/Shanghai各44个向量及并发验证通过；明确限制为这一个原生函数的行为对照，不执行任意用户脚本。

原工具包包含不同版本及可变类加载顺序，因此包版本号不能替代现场实际类来源确认。原Trans故障对照还观察到“完成回调触发、Result成功布尔为true但errors=1且留下部分文件”，本平台据此要求真实整批成功、完整产物和清理确认之后才允许FTP和Kafka确认。

发现旧Maven暂存目录会把不同版本自有JAR打入同一NAR：NiFi元数据为新版本，实际却可能执行旧类。已增加打包前清理、唯一版本/重复类检查、不可覆盖同版本的安装工具；新节点固定1.2.3，冻结任务保留原精确版本。

安装包SHA-256：`b872c3062d4201cdc71af145cd638534d781c49d0c005b1f1a9a15cbb844ced2`。两个自有JAR及27个治理类已核对。旧安装包未覆盖，备份位于独立运行目录`backups/compat-1.2.3-20260910-120553`。

- 字典为显式加载并随版本冻结；尚不逐批读取变化中的现场数据库。
- 新FTP采用独立批次目录与`_SUCCESS.json`，保留本地产物；原平铺目录扫描/删除源文件、命名时钟、接收端协议仍需现场适配。
- 失败或效果未知的已关联Kafka执行保留源占用，需核查，不提供抹除意图并盲目重跑的按钮。
- HBP/Face/BSP、图片及云存储等其他私有插件、规模/长时间运行、多副本存储和生产切换未验收。

要认定完全覆盖当前业务，需要实际消息、对应字典快照和原输出成对对照，并验证回写、接收端及失败恢复。现阶段不能仅凭合成图和原类向量认定完全替换。
