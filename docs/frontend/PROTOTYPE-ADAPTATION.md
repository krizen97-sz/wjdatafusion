# 外部原型与截图适配流程

## 1. 默认交付原则

除非用户明确要求严格像素级复刻，默认目标是：

> 业务与结构高保真，视觉语言项目化适配。

即使要求高视觉还原，也必须继续使用当前组件、图标和主题，不能用截图、
切片、大面积绝对定位或自绘控件模拟页面。

## 2. 编码前七步

### 第一步：理解业务目标

回答：

- 页面服务什么业务、主要用户是谁；
- 用户进入页面要完成什么任务；
- 首要信息与首要操作是什么；
- 成功、空、加载、错误、无权限和危险路径是什么。

无法从图片确认的字段或权限，先查当前模块接口和同类页面。只有冲突会影响
业务正确性时才暂停询问；轻微视觉细节采用最保守的一致方案。

### 第二步：提取信息架构

按语义区域拆解，而不是按矩形拆 DOM：

- 页面标题或当前任务区；
- 查询 / 筛选区；
- 状态概览；
- Tabs / 路由导航；
- 操作工具栏；
- 表格 / 列表 / 画布；
- 详情 / 表单；
- 分页；
- 加载、空、错误、权限和反馈。

### 第三步：识别组件语义

区分按钮、Tabs、筛选、Tag、Switch、Badge、表格、表单、Dialog、Drawer、
Descriptions、Progress、Steps、Empty、Loading、Icon、Chart 和导航。

视觉形状不是实现契约：胶囊可能是互斥筛选，彩色圆点可能是状态，卡片
可能只是普通内容容器，导航块也不一定是 Tabs。

### 第四步：搜索当前能力

按以下顺序搜索，每个核心模式至少找两个页面：

1. 当前模块；
2. `src/components`；
3. `REFERENCE-PAGES.md`；
4. 其他当前 RuoYi 页面；
5. 已安装 Element Plus 组件；
6. 当前图标目录和 `IconSelect`；
7. 当前 SCSS / CSS 变量和工具类。

### 第五步：形成组件复用计划

| 页面需求 | 现有实现 | 采用组件 | 参考文件 | 是否需要自定义 |
| --- | --- | --- | --- | --- |
| 示例：查询设备 | RuoYi 行内查询 | `el-form` + `RightToolbar` | `system/user/index.vue` | 否 |

### 第六步：形成原型适配表

| 原型区域 | 产品意图 | 原型表现 | 项目内映射 | 参考页面 | 适配说明 |
| --- | --- | --- | --- | --- | --- |
| 顶部切换区 | 切换设备类型 | 胶囊切换 | `el-tabs` 或 `el-segmented`，由语义决定 | `ipam/index.vue` / `autoInspection/cockpit.vue` | 保留切换关系，不复制胶囊外观 |
| 在线状态 | 读取设备状态 | 绿色圆点 | `DictTag` / `el-tag` | `system/post/index.vue` | 使用统一状态文案与语义色 |
| 主操作 | 新建设备 | 渐变按钮 | `el-button type="primary"` | `system/post/index.vue` | 保留操作层级，不使用渐变 |

### 第七步：明确保留与适配范围

优先保留：

- 信息架构、业务流程、操作层级；
- 内容分组、阅读顺序、交互关系；
- 重要状态、异常路径、响应式关系。

适配为项目规范：

- 字体、颜色、圆角、阴影、间距、动画；
- 按钮、Tabs、Tag、Switch、图标；
- 表格、表单、Dialog、Drawer 的视觉形态。

完成两张表后可以继续编码，不为一般设计判断等待确认。

## 3. 组件映射速查

| 原型表达 | 先判断 | 默认映射 |
| --- | --- | --- |
| 胶囊切换 | 内容切换还是筛选 | `el-tabs` / `el-segmented` / `el-radio-group` |
| 彩色圆点 | 状态还是数量 | `DictTag` / `el-tag` / `el-badge` |
| 开关 | 展示还是修改 | 展示用 Tag，修改用 `el-switch` |
| 卡片 | 真实独立表面还是分组 | 普通容器 / `el-card`，不默认新建 Card 样式 |
| 三点菜单 | 低频操作集合 | `el-dropdown` |
| 侧滑详情 | 是否需要保留页面上下文 | `el-drawer` |
| 浮层表单 | 简单编辑还是长流程 | `el-dialog` / `el-drawer` / 独立路由 |
| 插图空态 | 是否需要下一步 | `el-empty` + 一个主要操作 |
| 大图标结果 | 页面级完成/失败 | `el-result` |
| 自定义图标 | 是否已有近义正式图标 | Element Plus 图标 / `SvgIcon` / `IconSelect` |

## 4. 禁止的机械复刻流程

不得使用以下推理：

- “看到矩形就创建 div”；
- “看到下划线就手写 Tab”；
- “看到圆点就创建 StatusBadge”；
- “看到图标就画 SVG / CSS”；
- “按照坐标大量 absolute”；
- “切出图片作为可交互内容”；
- “用 Canvas 或截图复刻普通管理界面”。

## 5. 冲突处理

当原型与项目冲突：

1. 保留业务目标和信息架构；
2. 映射到现有组件；
3. 使用当前变量与图标；
4. 保留权限、接口和业务流程；
5. 最终报告说明适配项与假设。

若原型引入第二套 UI 框架、图标系统、交互范式或会改变业务正确性，停止
扩展范围并请求明确授权。

## 6. 实现后复核

- 业务目标、阅读顺序和主要操作是否完整；
- 是否使用至少两个相似页面作为证据；
- 是否复用了全局和模块组件；
- 是否出现新的按钮、Tabs、Switch、Tag、Dialog 或分页形态；
- 是否有不必要 absolute、硬编码值、内联 SVG、Emoji 或截图；
- 加载、空、错误、权限、提交中和危险确认是否完整；
- 窄屏、长文本、表格溢出和弹窗高度是否可用；
- `npm run ui:guard` 与相关测试是否通过。

最终报告至少列出：保留的原型意图、项目化适配、复用组件、自定义理由、
例外编号、验证结果和仍存在风险。
