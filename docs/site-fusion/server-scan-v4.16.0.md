# v4.16.0 服务器扫描、凭据核验与系统资料同步

## 附件检查结论

检查对象是用户提供的“3.5、设备扫描工具.zip”，SHA-256：
`32c740248f963e4cc4183dafbc71254e605a661ac3431b9fbb88da191fce2875`。

附件包含 `device_scanner.py`、`web_ui.py`、两份相同的 YAML 配置和 Windows x64 PE 可执行文件。
本次只静态分析附件，未运行 EXE、未导入附件候选密码，未验证二进制与源码同源。Python 源码可被语法解析，但不等于已完成附件程序的现场运行验收。

源码工作方式是：CIDR 展开、TCP 端口探测、按开放端口打标签、用候选密码尝试 SSH、hik 登录后 su root、导出 Excel。它不能读取设备原密码，“发现密码”实际上是已知候选密码认证成功。

原工具与本次需求的差异：

- SSH 认证只使用单个 `ssh.port`。附件配置为 55555，22 仅列入端口探测，2343 默认没有列入。
- 缺少独立 root 直登路径和严格的身份核验；将可配置用户名简单改成 root 不能正确表达页面的 hik/root 结果语义。
- 没有读取操作系统、内核或主机名的代码。
- `su` 的结束标记输出为 `__SU6066__END__`，等待表达式却匹配 `__SU6066END__`，会额外等待超时，不代表所有 su 都失败。
- 自动接受未知 SSH 主机密钥；候选密码明文写配置，成功密码写日志和 Excel；本地 Flask API 没有平台登录权限边界。
- 地址展开、并发与尝试次数缺少明确上限，网页部分通过 `innerHTML` 拼接数据。未对其 Windows 二进制作安全认证。

因此集成使用现有 Java 后端、JSch、AES 凭据服务和 Vue/Element Plus，未把 Flask 服务或 EXE 作为生产依赖。

## 确认后的需求

用户确认：允许输入网段发现并新建服务器；使用可配置授权候选凭据池且限制尝试；只采集 CentOS 等操作系统版本，不采集海康业务组件版本。用户授权本机数据库升级和 8080 重启，不升级 250、不扫描真实设备。

## 操作入口

1. 服务器管理列表的“扫描同步”：先选择现场。
2. 现场设备管理的设备清单工具栏“扫描同步”：当前现场自动带入；勾选已有服务器时可预填其 IP。
3. 设备清单的字段组选“扫描资料”，查看主机名、系统名称、系统版本、内核版本及最近完整成功采集时间。

没有向现场列表或现场配置页顶部增加设备按钮。已有服务器目录的操作系统列也显示同步后的系统名称/版本。

## 扫描流程与限制

### 配置

- 选择新服务器归属的当前现场子平台，已有服务器的归属不改变。
- 支持 IPv4 单地址、CIDR、完整起止 IP 段；分号、逗号、换行分隔，去重后最多 512 个地址。
- `/31`、`/32`按地址实际范围处理；普通 CIDR 排除网络地址和广播地址。拒绝回环、链路本地、组播等特殊范围。
- 默认全部检查 22、2343、55555，可选择其中端口；不接受任意命令、域名或其他端口作为本扫描入口。
- 每个现场最多 20 组候选凭据。每组明确为 root 直登，或 hik 登录后切换 root。hik 固定小写，密码保持原字符内容。
- 每次选 1 至 3 组，按选中顺序尝试；默认最多 1 组，可调至 3 组。密码加密存储，不采用附件内的明文密码作为默认值。

### 探测和确认

探测阶段只做端口连接和 SSH 指纹握手，不发送密码。所有选中的端口都探测，并显示开放/SSH/未连通状态。

确认清单中，已有记录优先预选其登记端口，否则预选首个可核验 SSH 端口。每个 IP 只选择**一个登录端口**，避免对同一主机的多个端口重复尝试密码。
管理员必须核对指纹并明确确认后才进入认证和自动同步，单批核验最多 128 台。
开放 SSH 不等于已确认物理设备类别；新目标仍由管理员从清单中选择。已经登记的硬件设备会跳过，同 IP 多条设备记录会要求先处理。

### 认证和同步

- 每组至多一次 SSH 密码认证，hik 路径再进行一次 su 密码核验；认证拒绝或 su 拒绝时才考虑下一组，组间等待 2 秒。
- root 必须确认 UID 0；免密 su、未进行密码认证、指纹变化或算法不兼容均不能当作密码正确。
- 全部入口共用最多 4 项认证并发；同一地址结束认证后冷却 60 秒。错误密码仍可能触发设备自己的锁定策略。
- 只在整条登录路径成功后同步该组经过核验的密码、端口和登录方式。root 直登不会删除原有 hik 凭据。
- 系统资料通过固定只读命令读取 `/etc/os-release`，兼容 CentOS/Red Hat 发行文件，另读取 `hostname`、`uname -r`；不会 source 版本文件或执行浏览器提交的命令。
- 资料采集使用同一已确认指纹及已验证登录账号再建立一次 SSH 会话；该连接/身份失败时停止同步。命令或资料不完整时保留上次完整扫描资料，不用空值刷新其时间。
- 已有服务器按现场和规范化 IPv4 匹配，使用工作簿版本摘要和现场锁防止覆盖并发修改；域名记录不自动按 DNS 合并。
- 新目标调用现有统一设备录入服务，凭据沿用 AES 加密，新服务器挂到选定子平台。扫描期间出现同 IP 新记录时不重复创建。
- 每台服务器的数据和扫描资料在同一事务同步，部分成功会保留，新增/修改按原操作记录流程留痕；密码只记录更新动作，不记录值。

扫描针对后端主机可达、已授权的网段，不会建立跨公安网/图像网等网络环境的通道。

## 任务生命周期

任务属于发起用户，同一现场最多一个活动/待确认任务，全局最多两项运行任务。探测和认证工作池均受限，不沿用原工具 200 线程默认值。

关闭窗口可后台继续，再打开恢复最近任务。停止操作不再处理后续目标；已经进入单台操作的结果可能完成，已同步的数据不撤销。
任务结果在当前后端实例内暂存约 30 分钟，重启后不恢复、不自动重试密码。多实例部署需要同实例会话粘性，当前没有分布式任务队列；升级前停止任务并等待完成。

授权池在确认时及每次后续尝试前重新核对，密码/登录路径修改或条目删除后不继续使用旧配置；仅改名不改变认证内容。已经发送到设备的请求无法撤回。
所有候选密码仅在请求和执行期间处理，任务响应不包含明文或密文，前端凭据提交不进入重复提交缓存。

## 验证及边界

- 后端覆盖地址范围、三端口、root/hik 路径、尝试预算、权限/任务所有者、指纹变化、并发版本、已有硬件保护、凭据加密及事务代理回滚。
- 本机回环隔离 SSH 服务验证实际握手、正确/错误密码、su 提示、免密 su、系统资料读取和指纹不一致；模拟命令应答不等同于已验收现场真实 PAM 或设备固件。
- 新 SQL 在关闭 TCP 监听的独立 MySQL 实例验证首次/重复执行及外键清理；本机业务库升级前已备份，并比对旧服务器、凭据和角色数据未变。
- 页面使用内存模拟 API 验证探测、指纹确认、新增/更新结果，不写入业务数据或发起真实网段扫描。实际部署页另外检查入口、配置加载和资料字段。
- 原生控件复用：现有 `EquipmentLoginCheck`、`EquipmentInventory` 的权限/状态模式，Element Plus Dialog/Form/Table/Steps/Drawer/Select/Checkbox，项目 Pagination 和图标；没有新增前端依赖或页面主题。
- 窄屏隐藏辅助步骤条，保留当前任务状态、进度和表格横向滚动；浅深色沿用主题变量，不新增 UI 例外。
