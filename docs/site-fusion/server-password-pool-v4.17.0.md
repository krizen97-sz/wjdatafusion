# v4.17.0 独立密码池

## 操作变化

服务器管理或设备清单的“扫描同步”入口不变。在“管理密码池”中，每条只维护名称和一个候选密码，无需指定账号或配对。新条目自动提供可修改的名称，编辑时密码留空保留原值；关闭抽屉清理输入，不回显已保存密码。

扫描任务选择密码池及登录策略：

- **自动匹配**：优先匹配 hik；已登记为 root 直登的设备直接匹配 root。只有所有候选 hik 密码均在 SSH 认证阶段被拒绝，才尝试 root 直登。
- **仅 root 直接登录**：只匹配 root，不尝试 hik。
- **仅 hik 登录后切换 root**：匹配 hik 后固定该密码，从同一池匹配 root，不回退 root SSH。

例如池内为 A、B、C，hik 实际使用 B、root 使用 C：程序先排除 hik 的 A，再确认 hik 的 B；后续固定 B，依次验证 root 的 A、B、C，不会继续尝试其他 hik 密码。支持两个账号使用同一密码。

## 尝试限制

每个账号默认最多使用 **1** 个不同候选密码，可调整到 **3**，按所选顺序取去重后的前 N 个；超出上限的密码不会继续尝试。密码池可存 40 条，以兼容旧 20 组配对凭据拆分后的数量。

去重只在任务执行内存中比较完整密码值，不修剪空格、不更改大小写。池中重复条目不会消耗额外的候选名额。不同账号分别受限，不枚举 N×N 组合。

hik 密码匹配成功后，尝试下一 root 密码会重新使用已验证的 hik 建立 SSH 会话。页面“路径校验次数”是完整校验调用次数，不等于不同密码数；后续采集系统资料还会用已验证账号连接一次。

保留单地址冷却 60 秒、最多 4 项并发、校验间隔 2 秒、先核对指纹和明确确认等约束。指纹变化、超时、身份异常、免密 su 等不会当作密码错误继续遍历。root 切换失败后不会改试另一 hik 密码或绕到 root SSH。账号可能存在更严格的锁定策略，应按设备策略设置上限。

仅完整登录路径及 root 密码核验通过才同步。停止或池内密码变化后，不再使用旧密码继续验证或同步；已经发往设备的认证无法撤回。密码不进入响应、任务结果或操作日志。新前端与后端必须配套，旧页面请求会提示刷新。

## 数据库部署

前置：完整 v4.16.0。若数据库仍在 v4.15.1，先执行已交付的 v4.15.1 至 v4.16.0 增量，再执行：

`WDF100.0/sql/support_upgrade_20260929_server_credential_password_pool_v4_17_0.sql`

新增 `sup_server_scan_credential.password_cipher VARCHAR(1024) NOT NULL DEFAULT ''`：

1. 旧记录 ID、名称和审计字段保留，原 root 密文逐字复制到新字段。
2. 旧 hik 密文复制为同一现场的独立条目，名称追加 ` / 2`，不重新加密。
3. 原 `hik_password_cipher`、`root_password_cipher`、`login_mode` 保留用于恢复；新程序只使用 `password_cipher`，不要混用新旧程序写入。
4. 原服务器、服务器账号、端口、平台归属、角色菜单及扫描资料表均不改写，无新增权限。

先停写并停止扫描任务，备份数据库、原 JAR、前端目录与配置。保持原 `support.credential.key` / `SUPPORT_AES_KEY`，不要重新生成密钥。备份含密码密文，应限制访问，不放入交付包或 Git。

以具有建列、读写该表及临时存储过程权限的 DBA 账号，在专用连接中整文件执行；支持 `DELIMITER`，禁止 `--force` 或多人并发迁移：

```bash
mysql --host='实际地址' --port=3306 --user='部署账号' -p \
  --default-character-set=utf8mb4 --database=rynew \
  < support_upgrade_20260929_server_credential_password_pool_v4_17_0.sql
```

出现 `SUCCESS` 后检查新字段和条目数。首次升级条目数应为原条目数加旧 hik/root 配对条目数，密文与原值相同；重复运行不重复拆分，不覆盖独立密码更新，也不复活已删除的拆分条目。数据复制事务失败会整体撤销，但新增列属于 DDL，不随该事务回退。

发现缺少 v4.16.0 表、已有新字段定义不兼容、旧候选配置不完整或自定义触发器时停止，由 DBA 核对后重跑。脚本未授权删除或清空历史数据；报错可能保留临时过程，重跑会清理重建。

回退应用时保留新字段和数据，恢复匹配的旧前后端及配置。旧程序不认识新增的独立密码条目，回退后应暂停扫描密码池维护，不能认为旧程序会自动得到新密码；需要恢复扫描功能时另行核对备份，不能直接覆盖整库或删除新数据。

## 验证

测试包括独立密码匹配、去重、root 直登、hik/root 不同密码、次数上限、错误/取消/指纹保护、日志脱敏，原 SSH 协议测试继续使用隔离回环服务。

数据库测试使用独立 MySQL 8.4.6、临时 socket、关闭 TCP 监听，覆盖首次拆分、重复执行、旧资料保留、字段异常及复制事务回滚；测试脚本为 `tools/site-fusion/test_server_credential_password_pool_v4_17_0.mjs`。

前端复用原 `EquipmentServerScanDialog`、Element Plus 表单、抽屉、表格、选择器、数字输入及项目 Pagination；未引入依赖、主题或 UI 例外。实际设备联网校验必须由用户在授权范围内另行验收，本次不会扫描真实设备。
