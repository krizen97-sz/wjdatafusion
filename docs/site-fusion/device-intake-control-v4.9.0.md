# 现场设备统一录入与管控方案

版本：v4.9.0。调研与实施日期：2026-09-22。

## 一、问题与结论

本次核查了现场列表、关系画布、服务器目录和机房管控图的实际页面与源码。问题不是缺少设备数据表，而是同一对象的入口和操作被拆散：

1. 现场列表只能先打开配置信息，再寻找平台、设备资产和机房图，首次录入路径过深。
2. 侧栏服务器管理页将新增、编辑等按钮设为隐藏，页面名称和实际能力不一致。
3. 图内新增原来分成硬件、服务器、批量三个不同流程，用户需要先理解内部数据分类。
4. 清单行只有“定位”，编辑和上架藏在后续面板或菜单中。
5. 未归属、未上架设备容易被平台范围和三维画面同时隐藏，造成“已经添加却找不到”的感觉。
6. 新现场没有机房、机柜时，上架配置会中断，没有连续回到原设备的路径。
7. 全现场范围的空平台值被旧平台值覆盖；首次打开弹窗与数据刷新存在时序问题。

统一原则：设备档案是管理对象；平台归属是业务关系；机房、机柜、U位是物理位置；端口与上联是网络关系。三维图是这些数据的联动视图，不应成为登记设备的前置门槛。

## 三、本次已实施

### 1. 可发现的统一入口

- 现场管理列表每行提供“新增设备”和“设备管理”。
- 关系画布工具栏提供同名入口，不必先进入某个子平台。
- 服务器目录恢复“新增设备”，先选现场后进入统一表单；行操作“设备管理”可定位对应服务器。
- 机房图及设备清单内均有明确的新增按钮。批量入口标为“批量录入服务器”，避免误认为支持所有硬件类型。

### 2. 单台录入

流程：选择现场 → 选择设备类型 → 填写最小必要信息 → 可选平台归属 → 保存。

| 设备类型 | 基本字段 | 可选扩展 |
| --- | --- | --- |
| 服务器 | 名称、地址、SSH端口、状态 | 子平台、操作系统、hik/root/其他账号凭据、备注 |
| 交换机、解码器、终端、网闸 | 名称、设备IP、网络环境、状态 | 平台、管理地址、厂商、型号、序列号、MAC、责任组织和联系人、凭据、备注 |

位置由图内配置，不再重复填写机房和U位自由文本。服务器沿用只归属子平台的规则，未选择时为待归属；硬件不选平台时为现场公共设备。

凭据默认隐藏、按需查看，后端沿用加密保存；统一创建接口不接收客户端指定的主键、密文或安装位置，不在通用操作日志记录请求明文。

保存后有三个明确去向：

- 查看设备：自动打开该设备详情。
- 配置安装位置：进入可视化U位选择；缺少机房或机柜时先创建，再回到原设备。
- 继续新增：保留设备类型和平台，清空名称、IP和凭据，避免串用上一台设备信息。

### 3. 统一管控

设备清单继续使用 Element Plus 查询表单、表格与项目 Pagination，不另造列表样式。提供设备类型、名称/IP、上架状态、未归属平台、未配置上联筛选，以及详情、编辑、位置操作。

从某个平台进入图时可切换“当前平台设备 / 全现场设备”；从现场列表直接进入设备管理时打开全现场清单。普通平台图仍默认隐藏两侧抽屉，维持画布优先。

机房、机柜、U位、上联、Excel导入导出继续复用原功能。本次没有把“正常/停用”重新解释为实时在线状态，也不将未配置上联当成故障。

### 4. 数据一致性

- 创建前校验现场存在、平台与现场一致；服务器不允许挂到主平台。
- 创建服务器与保存平台关系在同一事务内完成，归属失败时不留半成品。
- 重复地址沿用现有服务校验，失败保留表单；前端给出已登记设备提示。
- 修复全现场空平台值被旧平台覆盖的问题。
- 等待弹窗挂载后再执行打开操作；保存后等待拓扑请求完成再定位新设备。
- 无业务表结构修改、无迁移SQL；不重置历史数据和现有权限。

## 四、组件复用与边界

| 页面需要 | 现有实现 | 采用组件 | 参考文件 | 定制范围 |
| --- | --- | --- | --- | --- |
| 设备表单 | 原硬件、服务器表单 | el-dialog、el-form、el-radio-group、el-select、el-collapse | SiteConfigDialog.vue、support/server/index.vue | 统一字段入口、按类型组装提交数据 |
| 设备查询 | 原设备抽屉 | el-drawer、el-table、Pagination | EquipmentRoom3DWorkspace.vue | 新增筛选和行操作 |
| 上架配置 | 原机房、机柜和U位表单 | 现有表单及三维工作区 | EquipmentRoom3DWorkspace.vue | 连续配置与保存后定位 |
| 权限、状态 | RuoYi公共能力 | v-hasPermi、$auth、el-tag、el-alert | src/directive、src/plugins | 无新框架、无新权限体系 |

三维场景沿用 UIX-004 拓扑例外，没有新增图形引擎、图标库、UI框架或全局样式覆盖。手工新增表单和按钮使用现有浅深色主题。

## 五、后续优先级

| 优先级 | 建议 | 必要性与前提 |
| --- | --- | --- |
| P1 | 稳定资产编号与服务器/硬件身份统一 | IP会改变、不同网络可能重复，不能长期把IP视为唯一资产身份。需确定编号、历史映射与迁移策略。 |
| P1 | 五类设备统一Excel预检、差异预览、导入结果下载 | 当前服务器批量录入与拓扑导入各有职责；扩展前先定义新增/更新/跳过/冲突策略，密码空值不应默认清除。 |
| P1 | 厂商、型号、默认U高和端口模板 | 减少反复录入；需要业务维护模板，不能根据设备名称自动猜测接口。 |
| P2 | 生命周期：待部署、在用、维修、退役 | 与实时在线状态分开；退役保留历史，删除仅作为错误录入处理。需新增状态规则与权限。 |
| P2 | 网络环境内IP冲突校验和IPAM联动 | 公安网、图像网可能使用相同IP，先确定网络隔离边界和跨模块授权，避免误报。 |
| P2 | 设备变更、巡检、保修与工单联动 | 将“这是什么设备”与“它的健康和维护状态”串起来；不能用静态台账伪装实时监控。 |
| P3 | SNMP/SSH自动发现及采集差异确认 | 能降低录入成本，但必须有授权、采集范围、凭据托管和人工确认，不能直接覆盖人工配置。 |

以上为后续方案，不代表已经实现。优先把设备录入和人工维护闭环做稳定，再扩展CMDB与自动发现能力。

## 六、验收与运行

本地候选前端：端口5177；候选后端：端口18089。原8080未重启，生产250未发布。

验收包括统一入口、必填拦截、服务器保存后定位、重复地址拒绝、硬件及平台归属、连续新增、原生列表编辑和位置入口、上架引导、桌面和窄屏渲染。测试证据单独保存在工作区 output/device-intake，不纳入源码提交。

验证结果：

- 设备创建服务6项测试通过，覆盖现场、平台范围、保护字段、类型互斥和关系保存失败；其中回滚测试验证事务声明与错误抛出，不等同于真实数据库故障注入。
- 前端完整验证229项测试通过，其中现场规则9项；UI Guard为0错误、0警告，生产构建及154个JS产物的兼容性扫描通过。
- 后端 Maven 编译及打包通过；独立18089端口与本地数据库完成真实HTTP保存。
- 本地测试现场完成服务器创建、重复拒绝、交换机创建并归属主平台、连续新增清空字段、档案修改、未归属筛选，以及从空机房开始的连续上架。
- 1728×940和390×844截图检查通过；三维区域存在非空像素，恢复鸟瞰操作前后像素变化，窄屏新增表单可滚动访问保存、取消。
- 回归产生的两台设备、一座机房和一个机柜已通过正常删除流程清理；保留操作审计，不清除历史记录。

源码构建不等于生产上线，兼容性扫描也不等于低版本浏览器实机验收。权限继续按现有规则控制，尚未逐个使用非管理员角色进行浏览器验收。
