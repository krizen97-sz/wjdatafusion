# v4.14.1 设备配置修复

## 调整内容

1. 清单“配置”使用满高单元格容器，按钮在38px行内垂直居中。实际测量偏差由10px降为0。
2. 配置顶部并列显示“编辑设备”和“删除设备”。删除仍确认目标及影响范围，
   取消不会执行接口；处理中防重复提交，删除完成关闭被删除设备的配置。
3. “归属位置”拆为平台归属和安装位置两区。平台只展示一份完整父子路径，
   类型标签不承担长名称。位置分别列出机房、机柜和U位，操作按钮统一样式。
4. “凭据”页直接展示账号密码列表及就地编辑表单，不再打开另一套“凭据档案”。
   支持历史系统账号、HIK、root及其他已登记账号；密码默认隐藏，查看仍需明文权限。
5. HIK在界面统一大写。SSH用户名区分大小写，实际请求保持登记值；
   账号保存和工作簿修改密码不再强制把已有HIK用户名转成小写。

## 数据一致性

原遗漏原因是账号列表仅查询sup_server_credential，没有兼容sup_server中的
os_username/os_password_cipher。现在只读时合并两种来源，同名新记录优先，
包括已清空或停用的记录，避免旧密码重新出现。

历史账号在读取时不迁移、不落库。用户明确保存时，将该账号保存到现有账号表并
清除匹配的旧字段；密码留空沿用原密文，不要求用户重复提供密码。用户名改变、
来源已迁移或其他用户先行修改时会核对当前数据。旧账号删除有专用兼容路由，
只清理匹配账号，不删除设备或其他账号。

账号写操作共用现场/服务器锁，并用当前锁定读取核对账号。只更新账号相关字段，
不通过整行设备更新影响位置、平台等信息。删除同名账号同步清除其旧字段影子，
不自动恢复旧口令。请求不写明文日志或前端重复提交缓存。

仍保留既有账号API与数据表以兼容其他调用方，不把界面合并误做为删除业务数据。
没有新增表、字段或数据迁移脚本；远端若尚未升级v4.14.0，仍需先执行其独立SQL。
