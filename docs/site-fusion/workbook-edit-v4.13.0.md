# v4.13.0 设备清单编辑与统一配置

## 产品判断

原流程的主要问题不是缺少编辑按钮，而是同一台设备有多条重叠的修改路径：
清单的“详情、编辑、位置”分别打开不同容器，详情里又混有修改归属、
编辑档案和位置按钮，且即时保存与表单保存混用。

此次收敛为两种明确任务：

1. 清单编辑：对当前设备清单修改，统一保存或取消。
2. 单台配置：每行仅保留“配置”，按档案、归属位置、链路、凭据分区。
   普通设备编辑和硬件扩展属性均进入同一清单编辑流程。

## 操作流程

进入设备清单后点击“编辑”，出现“正在编辑”和修改数量。
设备名称与IP在各字段组中保持可见；桌面端固定关键识别列。
按任务切换“常用字段、基础档案、平台与位置、账号密码、硬件扩展属性”。
编辑期间收起筛选区、暂停自动同步、锁定范围和视图切换，跨页保留草稿。
保存前校验并确认；失败保留修改，可“重新核对”读取最新值并保留草稿。
取消、关闭或离开前确认未保存内容；浏览器刷新使用原生离开提醒。

| 信息 | 编辑方式 |
| --- | --- |
| 名称、IP/地址、系统、厂商型号、状态 | 原生输入或选择控件 |
| SSH端口 | 服务器专属，范围1至65535，历史端口保持原值 |
| 平台归属 | 多选当前现场平台；服务器新增归属只能选子平台 |
| 机房、机柜、U位 | 级联选择及整数输入，机柜容量与最终占用校验 |
| 硬件扩展 | 网络环境字典、MAC、序列号、责任信息及各设备类型专属字段 |
| 密码 | 不修改、设置新值、明确清空三种语义；清空再次确认 |
| 链路、多账号档案 | 统一配置窗口的专用分区，保留现有复杂关系编辑 |

清单编辑的是平台保存的资产档案，不会直接修改设备的网卡IP、操作系统
账户或真实系统密码，也不执行SSH命令。机房图仍保留可视化位置配置能力，
与表格共用相同位置字段和设备身份，不另建数据副本。

## 复用与边界

| 需要 | 既有能力 | 本次处理 |
| --- | --- | --- |
| Excel式清单 | 已安装RevoGrid，参考IPAM工作簿 | 虚拟表格和固定列；单元格内使用Element Plus控件 |
| 编辑状态 | el-tag、el-button、el-alert | 明确状态、错误和未保存提醒 |
| 分类与分页 | EquipmentRelationTree、Pagination | 保留原生树与计数，编辑中保护范围 |
| 关系及位置选择 | el-select、已有机房与机柜 | 不让文本冒充平台ID或机柜ID |
| 单台配置 | 现有Drawer、Tabs、Descriptions | 取消三个重复行入口，按任务分区 |

不引入第二套UI框架或电子表格引擎。表格编辑使用单元格输入/选择，
不包含任意Excel跨格粘贴、多人实时协作。当前仍为现场数据投影上的前端分页，
不宣称改为数据库分页；单次保存最多500台设备。
界面沿用UIX-004与UIX-011已有拓扑/设备工作簿边界，无新增例外。

## 后端与数据保护

- GET /support/equipment/workbook/{siteId}：返回编辑快照、版本摘要和选择项，
  不返回密码或密文；响应no-store。
- PUT /support/equipment/workbook：按设备类型、ID、版本及白名单字段提交。
- 校验类型权限、现场隔离、重复地址、平台层级、机房/机柜关系、U位范围与冲突。
- 按本批最终位置校验，支持同批协调调整；全部校验后在同一事务保存。
- 保存锁定现场及相关数据，以当前锁定读取核对关系和编辑版本。
- 只更新明确修改字段，不用旧整行接口清空未提交的位置、关系或凭据。
- 密码通过已有AES服务加密；请求/响应不写通用操作日志，不进入前端防重复
  提交的sessionStorage缓存。明文查看与设置新密码分开授权。
- 密码清空与撤销分开；同名账号存在多份凭据时不猜测修改目标，转到凭据管理选择。
- 每台设备记录修改前后差异和密码动作，不记录密码内容，沿用用户昵称记录。
- 修复旧硬件档案保存误重建未修改的平台关系；多平台硬件单条查询保持唯一返回，
  旧硬件写入也使用现场锁，与统一工作簿保存保持一致。
- 版本核对针对新工作簿接口，不宣称已改造全平台所有历史客户端的并发协议。
