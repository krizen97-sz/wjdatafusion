# 现场设备统一管控 v4.0.0 业务设计

## 一、业务目标

现场运维面对的是一批真实设备，而不是相互独立的“服务器记录”“硬件资产记录”和“机房摆放记录”。v4.0.0 将设备设为唯一管理对象，在同一张图中统一维护设备档案、平台归属、机房位置、物理链路和服务器凭据，减少重复录入、入口跳转和数据口径不一致。

## 二、数据所有权

| 业务对象 | 所有权与用途 | 约束 |
| --- | --- | --- |
| 设备 | 全现场统一清单的主对象，使用 `sourceType + sourceId` 形成稳定设备标识 | `SERVER` 与 `HARDWARE` 只表示底层来源，不再形成两套前端管理体系 |
| 平台归属 | 设备与主平台/子平台的业务关系 | 服务器可归属多个子平台；普通硬件保持单一平台归属 |
| 机房位置 | 设备所属机房、机柜及起止 U 位 | 位置是设备属性维度，清空位置不删除设备；同一机柜 U 位不得冲突 |
| 网络链路 | 设备与上联交换机的光口/电口关系 | 链路属于现场，删除设备时同步清理相关链路 |
| 凭据 | 服务器的账号密码能力 | 仅服务器开放凭据档案；密码明文查看继续受独立权限保护 |
| 机房与机柜 | 3D 场景的空间载体 | 地板尺寸、机柜容量和位置在同一工作区配置，不能越界或重叠 |

## 三、一张图交互结构

1. 左侧设备目录负责定位和批量选择，支持名称/IP、类型、平台和上架状态筛选。
2. 中央 3D 场景负责空间和拓扑认知，筛选结果同步控制图中设备及链路可见性。
3. 右侧检查器负责当前对象的统一编辑，设备、机柜和机房根据选择切换上下文。
4. 顶部只保留全局动作：新增设备、机房/机柜、数据导入导出、视角和同步。
5. 现场画布的所有设备入口直接打开统一管控图，并自动带入主平台或子平台范围。

## 四、统一操作规则

- 新增硬件和服务器都从管控图发起，新增后立即刷新设备目录与 3D 场景。
- 平台归属在设备检查器内维护，不再通过独立的“先建服务器、再关联”流程完成。
- 单个与批量删除使用同一事务编排，先校验设备属于当前现场，再按底层类型删除档案、位置关系和链路。
- 设备清单导出、3D 拓扑和前端目录都读取 `SupportEquipmentService` 的统一投影，禁止再次在页面或拓扑服务中分别拼装服务器与硬件数据。
- 机房布局 Excel 继续用于批量维护空间、位置和链路；现场完整压缩包导入导出流程保持不变。

## 五、兼容边界

- 不合并或迁移现有服务器表与硬件资产表，不修改既有业务数据。
- 保留原服务器、硬件和机房接口，统一权限可作为新入口权限，旧权限继续兼容。
- `support:credential:viewPlain` 仍是查看明文密码的必要权限，不因设备统一管理而放宽。
- 本版本只新增设备统一新增、修改和删除按钮权限，独立升级脚本可重复执行。
