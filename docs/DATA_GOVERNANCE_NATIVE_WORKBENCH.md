# 原生 Kettle 浏览器数据开发（v4.8.0）

## 实现目标

平台的“数据治理 → 治理工作台 → 数据开发”直接编辑原 KTR/KJB，并用用户提供工具包的原引擎与步骤类执行。浏览器中的参数、节点、连接和默认参数进入真实执行 XML；原 NiFi 模块保留在“已有治理流程”。

| 操作 | 当前实现 |
| --- | --- |
| 工具选择 | 原包静态目录与实际运行时合并；输入、处理、输出、作业分类，未就绪项明确禁用 |
| 参数配置 | 12 类原业务步骤的专用表单、常用输入/输出表单、原 metadata.allocate/getXML 骨架驱动的通用表单；可展开完整配置 |
| 图形编排 | 拖拽、端口连线、原条件分支、节点移动与整理；节点重命名同步引用，失败应用不修改原图 |
| 输入与连接 | 私有文件、任务内数据库连接、子转换绑定；密码加密保存，页面使用原秘密槽标识 |
| 调试 | 显式原生字段推导，真实节点预览、输入/输出/错误行、字段类型和原日志 |
| 运行 | 完整转换和原Job，停止、持久历史、完整输出下载；输出量不受预览20行限制 |
| 调度 | Quartz与时区，冻结XML、子任务、资产和执行时区；禁止重叠，失败暂停，未知结果不重放 |
| 交付 | 原FTP按不超过80个文件的批次执行，同一转换只运行一次，全部原生批次完成后才判定Job成功 |

## 原包与兼容边界

静态扫描有249个步骤实现、86个作业实现，共335项，不能把目录数量当成已验证可执行数量。当前运行时登记189个步骤，其中187个可加载；登记67个作业元数据，实际开放SPECIAL、TRANS、FTP_PUT三类。原18/24步业务使用的12类步骤全部可加载，实际来源为kettle-6.1.0.7.36.jar。

HBP/Face四个独立Kafka插件、普通plugins目录和Karaf/OSGi的缺口及原child-first加载机制，见 [插件差距审计](DATA_GOVERNANCE_KETTLE_PLUGIN_GAPS.md)。不将缺失依赖、仅目录可见或metadata可加载说成全部业务已经验收。

原FTP有硬编码80文件上限，达到后仍返回成功；only_new选项在本包中也可能先删除并覆盖同名文件。这些真实修改及分批适配见 [FTP批次机制](DATA_GOVERNANCE_KETTLE_FTP_BATCH_DELIVERY.md)。平台使用原FTP类，保留原文件名与字节、删除/重命名/ASCII行为。nativeProcessedFiles不是远端SHA校验，验收的远端核对另通过真实RETR完成。

## 输入、输出与快照

INPUT_DIR为本次run/input，保存上传输入和子KTR；WORK_DIR为run/output，只保存交付产物；JOB_DIR为run根。FTP不能选择INPUT_DIR、JOB_DIR或空目录，不接受输出中的链接或特殊文件。分批副本和manifest位于run/delivery，不能作为输出文件下载。

原XML中的未知字段、注释和扩展属性保留。每次运行与计划使用独立冻结包，含子转换及资产摘要；编辑子任务不改变已经冻结的计划。执行时区写入根data-rynew-timezone，缺省Asia/Shanghai；作业内子转换继承父作业JVM时区。显式字段时区仍由原步骤解释。

保存只进行原XML加载，不隐式连接数据库。获取字段标明metadata-only，不伪称完成原checkSteps或业务测试。字段转换显示失败返回原类型和有界诊断，不用伪造空值掩盖。

## 已完成的验收路径

- Chrome拖入CSV输入、配置脚本及文件输出，真实处理alice/张三/bob；修改脚本后文件从ALICE/张三/BOB变为web:ALICE/web:张三/web:BOB。
- 从通用表单给原SortRows增加字段并设置升序，真实四节点运行输出web:ALICE/web:BOB/web:张三。
- Chrome创建V8冻结计划，画布改到V9后定时触发仍生成V8结果；验收计划已暂停。
- 原Job的成功、失败和停止实际FTP测试；全匹配只上传输出，不上传输入CSV或子KTR，失败/停止不执行FTP。
- 161文件分别覆盖原FTP删除、保留、重命名和only_new，80/80/1三批，独立RETR逐文件SHA；第二批失败、停止与源变化均不推进后续批。
- 原18/24业务图使用隔离Kafka、PostgreSQL和FTP，保留42个步骤的处理摘要；详细计数与原80文件问题见 [整图验收](DATA_GOVERNANCE_KETTLE_BUSINESS_FIXTURE.md)。修复版整图结果以该文档和运行证据为准。
- 250隔离容器已验证原引擎离线输出、允许端点实际应答、禁止端点零连接、DNS TCP/UDP的内核DROP证据与自有资源清理，见 [Linux执行机制](DATA_GOVERNANCE_KETTLE_LINUX.md)。此记录不代替平台生产切换记录。

Chrome工具的文件选择器受扩展本地文件访问权限限制；本轮页面拖拽与运行已经实测，上传HTTP接口另已验证，不能把接口验证冒称浏览器上传权限已经开启。

## 组件复用

复用现有FlowDiagram、Element Plus Form/Table/Dialog/Drawer/Collapse/Tabs/Tag/Switch、Crontab、项目图标与主题。新增表单编辑原DOM，不创建第二套UI框架。运行结果与画布同页；详细字段表可展开。UI Guard及完整前端验证按每次源码变更复核，源文件与截图/运行包/私有凭据分开保存。

## 发布与回退

发布包须来自整合后的干净main提交，记录commit、原包/原JAR/执行class/镜像/前后端SHA。新worker只监听本机，平台通过私有token访问。Linux控制器管理独立非root容器，不把Docker socket或broker凭据挂入原引擎。

切换前保存旧前后端及私有配置，确认没有活动运行，再更换精确制品并核对健康、路由和浏览器。回退先暂停新计划并核查已发生的消费/交付；保留所有新运行与交付意图，不通过删除台账或重放原图恢复。

附件没有提供真实生产消息、字典和接收端对照数据；本轮整图是隔离合成数据验证。未支持的二进制导出、多result目标索引、独立HBP/OSGi插件与现场接收端仍需单独验收，不能据此声称所有335项或全部生产边界已覆盖。
